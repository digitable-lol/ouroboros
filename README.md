# Уроборос

**Показывает, как код исполнялся на самом деле: какие функции звались, с какими
доводами, что вернули и что бросили.**

Инструмент дописывает в исходник записи о вызовах. Программа запускается как
обычно, и каждый вызов оставляет две записи — на входе и на выходе. Дальше эти
записи читают глазами, отдают ИИ-агенту или превращают в готовые примеры для
спецификации — с прослеживаемостью до конкретного прогона.

Языки: Python, JavaScript/TypeScript, C, C++, Elixir. Готовится flang.

## Зачем он тебе

**«Я не понимаю, что тут происходит.»** Чужой проект, легаси, вчерашняя ошибка,
которая не воспроизводится. Прочитать сорок тысяч строк дорого; прогнать и
посмотреть, какие функции живые, с чем их зовут и что они возвращают, — дёшево.
Регулярно выясняется, что живых путей три, а остальное не исполнялось ни разу.

→ [Прологировать чужой код](docs/trace-existing-code.md)

**«ИИ пишет мне код и не понимает, как он исполняется.»** Модель, читающая
исходник, рассуждает о том, что **должно** произойти. По исходнику видно, что
**может** случиться; по трассе — какие ветви исполнялись, какие доводы
встретились, какие вызовы зависли и какие бросили исключение. Второго в исходнике
нет ни в каком виде.

→ [Чтобы ИИ понимал, как код исполняется](docs/with-ai.md)

## Поставить

```sh
brew install digitable-lol/tap/ouroboros
```

```sh
asdf plugin add ouroboros && asdf install ouroboros latest
```

Из исходников, подключение сервера MCP к Claude Code и Cursor — [Установка](docs/install.md).

> **Пока ни одна из этих двух строк ничего не поставит: выпуска ещё нет.**
> Формула и плагин лежат в [`packaging/`](packaging/) готовыми, но с пометками
> `TODO(выпуск)` на месте адреса архива, отпечатка и номера версии — их
> проставляют, когда выпуск появляется. Придумывать эти значения нельзя:
> по придуманным будут пробовать, и не сработает. См. [Состояние](#состояние).

## Первый прогон

Работа идёт через сервер MCP — обычный порядок подключения внешних инструментов
к ИИ-агенту. Отдельной команды в оболочке навык не описывает; всё, что ниже, —
операции сервера, которые зовёт агент.

```
create_project  →  write_file  →  execute  →  read_trace  →  fts_extract_examples
   черновик       обмазывает      запускает    смотрим        готовые примеры
                  при записи      как обычно   записи
```

1. **`create_project`** — заводит черновик: отдельное хранилище с историей, где
   можно портить что угодно.
2. **`write_file`** — обмазывает файл **до** сохранения. Код, который не
   разбирается, отвергается, а не сохраняется: полуобмазанного состояния не
   бывает.
3. **`execute`** — запускает вашу команду как обычно; переменная среды
   `OUROBOROS_DEBUG_INFO` указывает на файл записей `debug.info`.
4. **`read_trace`** — показывает снятое.
5. **`fts_extract_examples`** — превращает записи в примеры и возвращает отчёт со
   счётом отказов.

**Горячий файл целиком обмазывать нельзя** — нужные записи утонут в шуме. Для
таких файлов есть `wrap_functions`: обмазываются только названные функции.

## Что ты увидишь

**Записи трассы** — файл `debug.info`, только дописываемый JSONL, по одному
объекту JSON в строке. Две строки на вызов, связанные общим номером `id`:

```jsonl
{"p":"in","t":"<время входа>","id":"<номер>","ci":<ядро>,"th":"<поток>","fn":"<имя>","a":"<доводы>","k":"<именованные>"}
{"p":"out","id":"<номер>","fn":"<имя>","r":"<результат>","d":<секунды>}
{"p":"out","id":"<номер>","fn":"<имя>","x":"<Тип: сообщение>","d":<секунды>}
```

Схема у всех пяти языков **одна и та же**, до байта. Отсюда же берётся самый
дешёвый ответ на вопрос «где висит»: строка входа без парной строки выхода —
вызов вошёл и не вернулся. [Полный разбор ключей](docs/examples/trace-record.md).

**Отчёт о добыче** — сколько вызовов стало примерами и сколько отброшено, с
разбивкой по причинам (`skipped_by_reason`). Пустой счёт отказов — повод
проверить настройку, а не радоваться. [Подробнее](docs/examples/extraction-report.md).

**Примеры с происхождением** — у каждого пометка `// trace:` с файлом, функцией,
номером вызова и причиной, по которой этот вызов выбран. Пример без происхождения
— утверждение, которое нечем проверить.

> Схема выше взята из **контракта логгера** (`Ouroboros-Logger — Cross-language
> contract`) — документа, который задаёт формат записи всем пяти языкам. Он, как
> и сервер, в это хранилище пока не перенесён. А вот снимка **настоящего**
> прогона здесь нет ни на одной странице: снять его неоткуда, и **показ появится
> с выпуском**. Правдоподобная выдумка была бы хуже пустого места — по
> выдуманному выводу люди пишут разбор, и он ломается на первой же настоящей
> записи.

## Чего инструмент не делает

> Трасса записывает, **как код себя вёл**, а не как он должен себя вести.

Спецификация, выращенная из трассы, наследует ошибки программы **как закон**.
Это не оговорка внизу страницы, а устройство: [Границы](docs/limits.md) — самая
важная страница здесь.

## Состояние

**Это хранилище документации и спецификации.** Реализация (сервер `ouroboros-src`
и образ `ouroboros-logger`) переносится сюда отдельно; до тех пор документация
описывает поведение, снятое с работающего инструмента, а не задуманное.

Где что-то описано, но не перенесено, — сказано прямо, а не умолчано.

Страницы написаны по двум письменным источникам: навыку
[`skill/SKILL.md`](skill/SKILL.md) — он в хранилище есть — и **контракту логгера**
(`Ouroboros-Logger — Cross-language contract`), который задаёт формат записи всем
пяти языкам и сюда **пока не перенесён**. Где факт взят из второго, на странице
стоит «по контракту логгера»: читателю надо видеть, откуда что. Где молчат оба —
стоит «не описано», а не правдоподобная догадка.
