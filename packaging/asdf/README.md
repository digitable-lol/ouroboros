# Плагин asdf для уробороса

`asdf` держит рядом несколько версий одного инструмента и переключает их по файлу
`.tool-versions` в проекте. Этот каталог — плагин, который учит `asdf` ставить
уроборос.

```sh
asdf plugin add ouroboros
asdf install ouroboros latest
```

## Сейчас он ничего не поставит, и это нарочно

проставлено имя файла выпуска: его неоткуда взять, пока выпуск не собран.
Вместо имени там стоит `TODO(выпуск)`, а в начале скрипта — проверка, которая
останавливает установку и объясняет, что происходит.

Выдуманное имя было бы хуже: скачивание молча ушло бы в 404, и человек искал бы
причину в своей сети, в своём `asdf`, в своей версии `curl` — где угодно, кроме
этой строки.

Пока выпуска нет, ставьте способом «из исходников» —
[`docs/install.md`](../../docs/install.md).

## Откуда он берётся

`asdf` ждёт `bin/` в **корне** хранилища плагина. Здесь плагин лежит в
`packaging/asdf/`, то есть напрямую из этого хранилища он не поставится. При
выпуске эти файлы выкладываются отдельным хранилищем — `digitable-lol/asdf-ouroboros`,
— и оттуда уже ставятся:

```sh
asdf plugin add ouroboros https://github.com/digitable-lol/asdf-ouroboros.git
```

Короткое имя без адреса заработает после того, как плагин попадёт в общий список
плагинов `asdf`. Это отдельный шаг после выпуска, не раньше.

## Что внутри

| файл | когда зовётся | что делает |
|---|---|---|
| `bin/list-all` | `asdf list all ouroboros` | печатает версии — читает теги хранилища через `git ls-remote` |
| `bin/download` | `asdf install` | скачивает архив выпуска в `$ASDF_DOWNLOAD_PATH` |
| `bin/install` | `asdf install` | раскладывает скачанное в `$ASDF_INSTALL_PATH`, создавая `bin/` |

`bin/list-all` уже работает: адрес хранилища известен и проставлен. Пока тегов
нет, он честно печатает пустой список — выпусков не было.

## Что проставить при выпуске

Пометки `TODO(выпуск)` стоят в двух местах, оба подписаны прямо в коде.

**`bin/download` — имя файла выпуска.** Берётся со страницы выпуска на GitHub.
В имени можно пользоваться подстановками `${version}`, `${platform}` (`linux`
или `darwin`) и `${arch}` (`x86_64` или `arm64`) — скрипт подставит их сам. Если
выпуск окажется просто архивом исходников, то и имени не нужно: адрес
`…/archive/refs/tags/v${version}.tar.gz` у хранилищ на GitHub известен заранее.

**`bin/install` — какая из двух веток настоящая.** Написаны обе: установка из
исходников Python (когда в архиве есть `pyproject.toml`) и копирование готового
`bin/`. Форма выпуска пока не выбрана, поэтому лишнюю ветку вычеркивают при
первом выпуске, а оставшуюся сверяют с тем, что в архиве на самом деле. Если
ошибиться, установка положит пустой каталог, и выяснится это далеко от места
ошибки — поэтому ветки и не выбрана заранее наугад.

Отпечатка (`sha256`) плагин не проверяет: `asdf` скачивает по адресу и не ведёт
списка отпечатков, в отличие от Homebrew. Если проверка отпечатка нужна, её
добавляют в `bin/download` рядом со скачиванием, вместе с файлом отпечатков из
выпуска.

## Что должно стоять на машине

| нужно | когда |
|---|---|
| Python 3.12 или новее | всегда — `bin/install` проверяет до установки |
| `libclang` | только для C и C++ |
| Node | только для JavaScript и TypeScript |

`libclang` и Node плагин не ставит: они нужны не всем, а только тем, кто
обмазывает код на этих языках.

## После установки

Уроборос работает как сервер MCP — агент запускает его сам. Настройка сервера и
места, куда её кладут разные клиенты, — [`docs/install.md`](../../docs/install.md).
