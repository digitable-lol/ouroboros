# Плагин asdf для уробороса

`asdf` держит рядом несколько версий одного инструмента и переключает их по файлу
`.tool-versions` в проекте. Этот каталог — плагин, который учит `asdf` ставить
уроборос.

```sh
asdf plugin add ouroboros https://github.com/digitable-lol/ouroboros.git
asdf install ouroboros latest
asdf set ouroboros latest
```

Проверить:

```sh
ouroboros languages
```

```json
{"languages": ["python", "javascript", "c", "cpp", "elixir", "go"]}
```

Установка проверена целиком на этом хранилище: `plugin add`, `list all`,
`install`, обмазка файла через обёртку asdf, запуск и чтение записей, а также
запуск сервера MCP. При выпуске 0.4.0 подопытным был файл на Go — метод с
получателем по указателю, — и в записи попало `(*Счётчик).Добавить`: смещения
считаются в байтах, поэтому кириллица в именах ничего не ломает.

> **Правило `insteadOf` в `~/.gitconfig` ломает `asdf plugin add`.** Если у
> человека адреса `https://github.com/` переписываются на `git@github.com:`,
> клон плагина уходит по ssh и падает без ключа. Клонирует `asdf`, а не мы, так
> что защитить это изнутри плагина нельзя — только снять правило на время. Свои
> обращения к git плагин уже защищает: см. `GIT_CONFIG_GLOBAL=/dev/null` в
> `bin/list-all`.

## Почему адрес указывается явно

По короткому имени (`asdf plugin add ouroboros`) `asdf` ищет плагин в общем
списке плагинов asdf. Попасть туда — отдельный шаг, который ещё не сделан,
поэтому пока адрес хранилища пишут полностью.

## Где что лежит

`asdf` ждёт `bin/` в **корне** хранилища плагина. Поэтому в корне лежат три
однострочных файла [`bin/`](../../bin/), которые передают работу настоящему
плагину — сюда. Отдельного хранилища для плагина не нужно: он ставится прямо из
этого.

Правьте файлы здесь, а не в корневом `bin/`.

| файл | когда зовётся | что делает |
|---|---|---|
| `bin/list-all` | `asdf list all ouroboros` | печатает версии — читает теги хранилища через `git ls-remote` |
| `bin/download` | `asdf install` | скачивает архив исходников тега в `$ASDF_DOWNLOAD_PATH` |
| `bin/install` | `asdf install` | ставит пакет в собственное окружение и выносит наружу его команды |

## Как устроена установка

**`bin/download`** берёт архив исходников по адресу вида
`…/archive/refs/tags/v<версия>.tar.gz`. GitHub отдаёт такой архив для любого тега
сам, отдельно собирать и выкладывать файл не нужно — поэтому подстановок
платформы и процессора здесь нет — и поэтому же плагин начинает работать сразу,
как только появился тег.

Отпечатка (`sha256`) плагин не проверяет: `asdf` скачивает по адресу и не ведёт
списка отпечатков, в отличие от Homebrew. Скачивание идёт по HTTPS с GitHub.

**`bin/install`** проверяет, что на машине есть Python 3.12 или новее, создаёт
для версии отдельное окружение в `libexec/` и ставит туда пакет. Наружу, в
`bin/`, выносятся **только** `ouroboros` и `ouroboros-mcp`.

Список вынесенных имён явный, и это важно: вместе с пакетом в окружение
приезжают команды его зависимостей — `httpx`, `jsonschema`, `mcp`, `uvicorn`,
`dotenv` и другие. `asdf` делает обёртку на каждое вынесенное имя, то есть при
выносе «всего подряд» они попали бы человеку на `PATH` и заслонили бы настоящие
программы с теми же именами.

В конце `bin/install` запускает поставленное (`ouroboros languages`) и падает,
если оно не работает: пустой или нерабочий каталог версии лучше обнаружить сразу.

## Что должно стоять на машине

| нужно | когда |
|---|---|
| Python 3.12 или новее | всегда — `bin/install` проверяет до установки |
| `gcc`/`g++`, `node`, `elixir` | только чтобы собрать и запустить обмазанный код на этих языках |

`libclang` приезжает зависимостью пакета, `@babel/parser` лежит внутри пакета —
доставлять их отдельно не надо.

## После установки

Работать можно сразу командой `ouroboros`. Если инструментом будет пользоваться
ИИ-агент, добавьте в настройку клиента:

```json
{ "mcpServers": { "ouroboros": { "type": "stdio", "command": "ouroboros-mcp" } } }
```

Подробнее — [`docs/install.md`](../../docs/install.md).
