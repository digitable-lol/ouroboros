# Начало работы

Эта страница — про **порядок работы**: какие операции есть, в каком порядке их
зовут и что проверить в конце.

Поставить инструмент и подключить сервер — [Установка](install.md). Если вы
пришли с конкретной задачей, начните с неё, а сюда вернитесь за подробностями:

- [Прологировать чужой код](trace-existing-code.md) — понять, что происходит в
  проекте, которого вы не писали.
- [Чтобы ИИ понимал, как код исполняется](with-ai.md) — дать модели то, что было
  на самом деле, вместо рассуждений по исходнику.

## Три инструмента, а не девятнадцать

Операций девятнадцать, но агенту в разговор кладутся три. Иначе девятнадцать
описаний висят в каждом обращении и вытесняют работу:

1. **`ouroboros_capabilities`** — какие есть группы операций: `instrument`,
   `sandbox`, `trace`, `fts`, `clang`.
2. **`ouroboros_describe`** с одной группой — описания её операций: что каждая
   принимает.
3. **`ouroboros_invoke`** с именем операции и доводами — собственно работа.

**Не вызывайте операцию, описания которой не прочли.** Это не совет по стилю: у
операций разные доводы, и угаданный довод молча уводит в сторону.

Неудача возвращается разобранным ответом с приложенным описанием операции, а не
исключением. Настоящей ошибкой связи считается только испорченный вызов самого
порядка обмена.

## Первый прогон

```
create_project  →  write_file  →  execute  →  read_trace  →  fts_extract_examples
   черновик       обмазывает      запускает    смотрим        готовые примеры
                  при записи                   записи
```

1. **`create_project`** — заводит черновик: отдельное хранилище с историей, где
   можно портить что угодно.
2. **`write_file`** — обмазывает файл **до** сохранения и делает по одной записи
   в историю на операцию. Код, который не разбирается, **отвергается, а не
   сохраняется**: полуобмазанного состояния не бывает. *По контракту логгера* это
   устроено так: часть, которая не смогла разобрать свой вход, поднимает
   `CorruptedSourceError`, а черновик превращает её в отклонённую запись — файл
   не сохраняется и в историю не попадает.
3. **`execute`** — запускает вашу команду как обычно. Переменная среды
   `OUROBOROS_DEBUG_INFO` указывает на файл записей `debug.info` в черновике.
   Заодно в тот же файл дописывается служебная запись о самой команде — что
   запускалось, с каким кодом возврата и каким выводом.
4. **`read_trace`** — показывает снятое. Посмотрите сюда прежде, чем добывать:
   если записей нет, дальше идти незачем.
5. **`fts_extract_examples`** — превращает записи в примеры и возвращает отчёт со
   счётом отказов.

Когда всё готово, **`finish`** переносит черновик в чистовик, оставляя за бортом
историю (`.git`) и файл записей `debug.info`.

> Снимается ли при переносе сама обмазка — **не описано** ни в навыке, ни в
> контракте логгера. Пока не проверили на своей установке, считайте, что не
> снимается, и смотрите глазами, что уехало наружу.

## Что вы увидите в записях

Каждый вызов даёт **две строки**, связанные общим номером `id`: вход
(`"p":"in"`) и завершение (`"p":"out"`) — при возврате или при исключении. Схема
одна и та же у всех пяти языков.

```jsonl
{"p":"in","t":"<время входа>","id":"<номер>","ci":<ядро>,"th":"<поток>","fn":"<имя>","a":"<доводы>","k":"<именованные>"}
{"p":"out","id":"<номер>","fn":"<имя>","r":"<результат>","d":<секунды>}
{"p":"out","id":"<номер>","fn":"<имя>","x":"<Тип: сообщение>","d":<секунды>}
```

Разбор всех ключей — [Запись трассы](examples/trace-record.md). Настоящего
снимка прогона в документации нет: **показ появится с выпуском**.

## Две вещи, на которых спотыкаются в первый раз

**Имена доводов.** В записи имён позиционных доводов нет по устройству: поле `a`
— это одни значения. У Python имена читаются из подписи функции. У TypeScript и
C — **нет**; их передают списком (`param_names`), иначе все записи будут
отброшены с причиной `no-parameter-name`. Про C++ и Elixir навык молчит —
задавайте вручную. Подробнее: [Языки](languages.md).

**Горячие файлы.** `wrap_file` на файле с миллионом вызовов в секунду топит
нужные записи в шуме. Для таких файлов есть `wrap_functions`: обмазываются только
названные функции.

## Что проверить, прежде чем считать работу сделанной

- Отчёт о добыче прочитан: `skipped_by_reason` либо пуст, либо понятен.
- У каждого примера есть пометка `// trace:` с номером вызова.
- Правила и свойства написал человек, а не трасса.
- Прогон затронул те ветви, о которых спецификация берётся говорить.
- Спецификация прогнана через проверку (в навыке — `fts-gate check`), и отказ
  **прочитан, а не обойдён**.
- Никто не считает, что зелёная отметка означает правильную программу.
