# Уроборос

**Показывает, как код исполнялся на самом деле: какие функции звались, с какими
доводами, что вернули и что бросили.**

Инструмент дописывает в исходник запись о вызовах. Программа запускается как
обычно, и каждый вызов оставляет две строки JSON — на входе и на выходе.

Языки: Python, JavaScript/TypeScript, C, C++, Elixir, Go, Java, C#. Схема записи
у всех одна.

## Четыре шага

**Поставить:**

```sh
uv tool install git+https://github.com/digitable-lol/ouroboros
```

**Дописать запись о вызовах:**

```sh
ouroboros wrap-file stats.py
```

```json
{"ok": true, "path": "stats.py", "language": "python", "functions_wrapped": 3, "runtime_header": "ouroboros_runtime.py"}
```

**Запустить как обычно:**

```sh
python3 stats.py
```

**Прочитать:**

```sh
ouroboros trace debug.info --outcome raised
```

```json
    {
      "index": 5,
      "started": "2026-08-28T23:39:45.166",
      "call_id": "ef71eb89-6727-4cdf-a3b7-2ea54cff81e3",
      "name": "average",
      "args": "[]",
      "kwargs": "",
      "outcome_kind": "raised",
      "outcome": "ZeroDivisionError: division by zero",
      "duration": 3e-06,
      "cpu": null,
      "thread": "2864987.129949101195776"
    }
```

`args: "[]"` — вот чего нет в отслеживании стека. Стек говорит, **где**
сломалось; запись говорит, **с чем позвали**.

Полностью, с исходником и выводом каждого шага, — в
[README хранилища](https://github.com/digitable-lol/ouroboros/blob/main/README.ru.md#четыре-шага).

## Что лежит в `debug.info`

Только дописываемый файл, по одному объекту JSON в строке. Две строки на вызов,
связанные общим `id`:

```jsonl
{"p":"in","t":"2026-08-28T23:39:45.166","id":"e668ee33-…","ci":-1,"th":"2864987.129949101195776","fn":"average","a":"[12, 30, 18]","k":""}
{"p":"out","id":"e668ee33-…","fn":"average","r":"20.0","d":2e-06}
```

Отсюда самый дешёвый ответ на вопрос «где висит»: строка входа без парной строки
выхода — вызов вошёл и не вернулся. [Полный разбор ключей](examples/trace-record.ru.md).

## Если читать только одно

Читайте [Границы](limits.ru.md).

> Записи фиксируют, **как код себя вёл**, а не как он должен себя вести.

Программа с ошибкой даёт записи, в которых ошибка выглядит нормой. Инструмент не
скажет, что код неправильный, — он скажет, что код делает.

## Состояние

**В хранилище лежит рабочий инструмент**, а не только его описание: пакет
`ouroboros-logger` <!--state:version-->0.6.1<!--/state-->, командная строка на 17 команд, сервер MCP на 17
средств, <!--state:tests-->1257<!--/state--> проверок. Всё, что показано на
страницах, — вывод настоящих прогонов на обычной машине с Linux; выводы всех
восьми языков сняты по отдельности, и их можно снять заново одной командой —
[Замеры](measurements.ru.md).

Установка проверена целиком, а не «по виду правильно»: `uv tool install`,
`brew install digitable-lol/tap/ouroboros` вместе с `brew test`,
`asdf plugin add` вместе с `asdf install` — и после каждой поставленный
инструмент обмазывал файл, запускал его и читал записи.

Что известно сломанным: обмазка — правка исходника, а не наблюдение со стороны,
и она умеет менять поведение программы, а не только время её работы. Проверенные
случаи, то, что уже починено, и то, что остаётся как есть осознанно, собраны в
[Границах](limits.ru.md#где-обмазка-меняет-поведение-программы). Числа к ним — в
[Замерах](measurements.ru.md).

Хранилище целиком: [digitable-lol/ouroboros](https://github.com/digitable-lol/ouroboros).
