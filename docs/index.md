# Уроборос

**Показывает, как код исполнялся на самом деле: какие функции звались, с какими
доводами, что вернули и что бросили.**

Инструмент дописывает в исходник записи о вызовах. Программа запускается как
обычно, и каждый вызов оставляет две записи — на входе и на выходе. Дальше эти
записи читают глазами, отдают ИИ-агенту или превращают в готовые примеры для
спецификации — с прослеживаемостью до конкретного прогона.

Языки: Python, JavaScript/TypeScript, C, C++, Elixir. Готовится flang.

## Зачем он тебе

**«Я не понимаю, что тут происходит.»** Чужой проект, легаси, вчерашняя ошибка,
которая не воспроизводится. Прочитать сорок тысяч строк дорого; прогнать и
посмотреть, какие функции живые, с чем их зовут и что они возвращают, — дёшево.
Регулярно выясняется, что живых путей три, а остальное не исполнялось ни разу.

→ [Прологировать чужой код](trace-existing-code.md)

**«ИИ пишет мне код и не понимает, как он исполняется.»** Модель, читающая
исходник, рассуждает о том, что **должно** произойти. По исходнику видно, что
**может** случиться; по трассе — какие ветви исполнялись, какие доводы
встретились, какие вызовы зависли и какие бросили исключение. Второго в исходнике
нет ни в каком виде.

→ [Чтобы ИИ понимал, как код исполняется](with-ai.md)

## Поставить

```sh
brew install digitable-lol/tap/ouroboros
```

```sh
asdf plugin add ouroboros && asdf install ouroboros latest
```

Из исходников и подключение сервера MCP к Claude Code и Cursor —
[Установка](install.md).

> **Пока ни одна из этих двух строк ничего не поставит: выпуска ещё нет.**
> Формула и плагин лежат в хранилище готовыми, но с пометками `TODO(выпуск)` на
> месте адреса архива, отпечатка и номера версии. Придумывать эти значения
> нельзя: по придуманным будут пробовать, и не сработает. См.
> [Состояние](#состояние).

## Что ты увидишь

Файл `debug.info` — только дописываемый JSONL, по одному объекту JSON в строке.
Две строки на вызов, связанные общим номером `id`:

```jsonl
{"p":"in","t":"<время входа>","id":"<номер>","ci":<ядро>,"th":"<поток>","fn":"<имя>","a":"<доводы>","k":"<именованные>"}
{"p":"out","id":"<номер>","fn":"<имя>","r":"<результат>","d":<секунды>}
{"p":"out","id":"<номер>","fn":"<имя>","x":"<Тип: сообщение>","d":<секунды>}
```

Схема у всех пяти языков одна и та же, до байта. Отсюда же самый дешёвый ответ на
вопрос «где висит»: строка входа без парной строки выхода — вызов вошёл и не
вернулся. [Полный разбор ключей](examples/trace-record.md).

## Если читать только одно

Читайте [Границы](limits.md).

> Трасса записывает, **как код себя вёл**, а не как он должен себя вести.

Спецификация, выращенная из трассы, наследует ошибки программы **как закон**.
Поэтому разделение жёсткое: пример берётся из трассы, правило пишет человек или
синтезатор, свойство — только человек.

## Состояние

**Это хранилище документации и спецификации.** Реализация (сервер
`ouroboros-src` и образ `ouroboros-logger`) переносится сюда отдельно; до тех пор
документация описывает поведение, снятое с работающего инструмента, а не
задуманное.

Где что-то описано, но не перенесено, — сказано прямо, а не умолчано.

Страницы написаны по двум письменным источникам: навыку
[`skill/SKILL.md`](https://github.com/digitable-lol/ouroboros/blob/main/skill/SKILL.md)
— он в хранилище есть — и **контракту логгера** (`Ouroboros-Logger —
Cross-language contract`), который задаёт формат записи всем пяти языкам и сюда
**пока не перенесён**. Где факт взят из второго, на странице стоит «по контракту
логгера»: читателю надо видеть, откуда что. Где молчат оба — стоит «не описано»,
а не правдоподобная догадка.

Снимка настоящего прогона нет ни на одной странице: снять его пока неоткуда, и
показ появится с выпуском.

Хранилище целиком: [digitable-lol/ouroboros](https://github.com/digitable-lol/ouroboros).
